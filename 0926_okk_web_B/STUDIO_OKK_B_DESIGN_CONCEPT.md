# STUDIO OKK — B안 디자인 컨셉

버전 0.4 · 2026.09.26 · 디자인 및 인터랙션 설계 문서

## 1. 컨셉: BLUE PLAYGROUND

**구름 사이에서 펼쳐지는, 캐릭터와 상상력의 놀이터.**

선명한 코발트블루 하늘에 폭신한 구름, 풍선처럼 부풀어 오른 글자, 귀여운 오키키와 손그림 스티커를 배치한다. 첫 화면은 즐거운 입체 포스터처럼 보이고, 스크롤하면 오키키가 몸을 돌려 오른쪽으로 이동하면서 왼쪽에 스튜디오의 이야기를 위한 공간이 열린다. 시각적인 즐거움이 회사 소개와 작업 탐색으로 이어지는 구성이다.

핵심 인상: **선명함 · 폭신함 · 장난스러움 · 친근함 · 입체감**.

### 기준과 적용 범위

- 기반 자료: `STUDIO_OKK_PRD_v0.3.md`, `README.md`, 현재 `public`의 화면과 인터랙션.
- 디자인 레퍼런스: 사용자가 제공한 `자료/대표캐릭터/배경.jpg` 포스터.
- 사용자 지정 사항: 블루 그라데이션, 흰 구름, 둥근 입체 타이포, 3D 캐릭터, 낙서·스티커, 스크롤 진행도에 연결된 Y축 180도 회전과 오른쪽 이동, 역방향 재생, 모바일 겹침 방지.
- 페이지 구성: B안은 원페이지로 구성하며 GNB 선택 시 같은 페이지의 해당 섹션으로 앵커 이동한다.
- 추가 지정 사항: 포트폴리오 목록은 캐릭터 자판기로 구성하고, 실제 자판기처럼 각 선택 버튼을 누르면 해당 작업 상세 화면을 보여준다. 클라이언트는 간결한 띠배너로 표현한다.
- 이 문서의 색상 보조값, 카피, 배치 비율, 진행 구간은 시안 제작을 위한 제안이다. 회사 소개 문구와 실제 제공 서비스는 확정 자료로 교체한다.
- 이번 산출물은 B안 설계 문서다. 기존 화면과 PRD는 보존하며, 이후 B안 구현 시 이 문서를 해당 안의 시각·히어로 동작 기준으로 사용한다.

## 2. 기존안과 B안의 차이

| 항목 | 기존안 | B안 |
| --- | --- | --- |
| 배경 | 밝은 중성색과 블루 포인트 | 코발트블루에서 하늘색으로 이어지는 공간 |
| 첫인상 | 정돈된 포트폴리오와 큰 로고 타이포 | 캐릭터가 중심인 입체 포스터 |
| 그래픽 | 평면 타이포와 작은 스티커 | 폭신한 구름, 볼륨 있는 글자, 종이·낙서 콜라주 |
| 히어로 동작 | 원 확대, 인사, 글자 낙하와 스크롤 지점 반응 | 스크롤 위치에 따라 캐릭터 회전·이동과 소개 전환 |
| 메인 흐름 | 히어로 → 작업 → 클라이언트 → 문의 | 히어로 → 같은 장면 안의 회사 소개 → 작업 → 클라이언트 → 문의 |

B안의 히어로에는 기존 원 확대·글자 낙하 연출을 중첩하지 않는다. 페이지 진입 시 완성된 첫 장면을 보여주고, 사용자의 스크롤이 장면 전환을 이끈다. B안은 회사 소개·작업 목록·클라이언트·문의를 하나의 페이지에 통합한다. 기존 소개와 작업 콘텐츠, 공통 문의 모달과 문의 처리 기능은 재사용하며, 작업 상세는 페이지 안의 모달로 제공하는 것을 제안한다.

## 3. 비주얼 시스템

### 색상

| 역할 | 제안 색상 | 적용 |
| --- | --- | --- |
| 브랜드 코발트 | `#004EEA` | 기존 브랜드색 유지, 하늘의 중심색, 주요 버튼 |
| 선명한 블루 | `#0866FF` | 히어로 상단과 중간 그라데이션 |
| 하늘색 | `#81D5FF` | 캐릭터 뒤의 밝은 빛, 전환 배경 |
| 구름 화이트 | `#F7FBFF` | 구름, 타이포, 콘텐츠 패널 |
| 딥 네이비 | `#102653` | 본문, 메뉴, 밝은 배경 위 제목 |
| 스티커 핑크 | `#FF9BDA` | 별 모양 스티커, 작은 강조 |
| 메모 옐로 | `#FFF071` | 메모와 화살표 포인트 |

히어로는 상단과 바깥쪽을 진한 블루, 중앙과 아래쪽을 밝은 하늘색으로 만든다. 캐릭터 뒤에는 넓고 부드러운 밝은 영역을 두어 파란 비니가 배경에 묻히지 않게 한다. 핑크와 노랑은 작은 장식에만 사용한다. 소개 장면에서는 왼쪽을 흰색에 가까운 하늘색으로 밝히고 오른쪽에 블루를 남긴다.

### 타이포그래피

- 히어로: 짧은 영문을 2~3줄로 크게 배치한다. 둥글고 두꺼운 글자에 흰색 또는 옅은 핑크 표면, 부드러운 음영과 하이라이트를 적용한다. 글자 주변에 숨 쉴 여백을 둔다.
- 제목 제안: `MAKE / SOMETHING / OKK!`. 레퍼런스의 제작 행사 문구를 그대로 회사의 메시지로 사용하지 않는다.
- 소개 제목: 둥근 인상의 굵은 한글 서체, 데스크톱 44~64px / 모바일 28~36px 제안.
- 본문: Pretendard 또는 기존 시스템 대체 서체, 16~18px, 행간 1.65~1.8. 장문에는 입체 효과나 외곽선을 적용하지 않는다.
- 입체 영문을 이미지로 제작하더라도 동일한 의미의 HTML 제목을 제공한다. 최종 서체와 사용 권한은 에셋 준비 단계에서 확인한다.

### 캐릭터와 장식

오키키를 히어로의 주인공으로 사용한다. 분홍빛 몸, 파란 비니, 표정과 재질은 기존 캐릭터 자료를 따른다. 오키몽은 하단 소개나 작은 보조 장면에 제한적으로 활용한다.

구름은 화면 상단 모서리와 하단 가장자리에 모아 무대를 감싸게 한다. 손그림 하트·별·화살표와 종이 스티커는 외곽에 3~5개 정도 배치하는 것을 시작값으로 삼는다. 종이는 살짝 기울이고 접힌 그림자를 주되, 본문 패널과 실제 버튼은 수평으로 정렬한다.

포스터 전체를 배경 한 장으로 깔지 않고 **하늘 / 뒤쪽 구름 / 타이포 / 캐릭터 / 앞쪽 구름·스티커 / 정보·UI**로 분리한다. 각 요소의 이동과 반응형 재배치가 가능해야 한다. 장식은 클릭을 가로막지 않으며, 실제 버튼과 혼동되는 표현을 피한다.

## 4. 히어로와 회사 소개 구성

### 원페이지 정보 구조와 GNB

페이지 순서는 **Home(히어로) → Studio(회사 소개) → Works(캐릭터 자판기) → Clients(띠배너) → Contact(문의)**로 구성한다. 히어로와 회사 소개는 하나의 연속 스크롤 장면 안에 둔다.

| GNB 항목 | 앵커 | 도착 상태 |
| --- | --- | --- |
| STUDIO OKK 로고 | `#home` | 히어로의 첫 장면 |
| Studio | `#studio` | 캐릭터 회전이 완료되고 회사 소개가 완전히 보이는 위치 |
| Works | `#works` | 캐릭터 자판기의 제목과 첫 진열칸 |
| Clients | `#clients` | 클라이언트 로고 띠배너 |
| Let’s talk | `#contact` | 문의 안내와 문의하기 버튼 |

- GNB는 상단에 고정하고, 실제 `href="#섹션ID"`를 가진 링크로 구성한다. 선택 시 해당 위치로 부드럽게 이동하고 URL 해시를 갱신한다. 모션 감소 설정에서는 즉시 이동한다.
- 고정 헤더 높이와 여백을 반영해 섹션 제목이 가려지지 않도록 한다. 일반 섹션은 `scroll-margin-top` 등으로 도착 위치를 보정한다.
- `#studio`는 sticky 컨테이너의 시작점이 아니라 소개가 완전히 보이는 진행도 약 90%의 실제 스크롤 위치에 대응시킨다. 해시 직접 접속·새로고침·화면 크기 변경에도 동일한 상태가 보이도록 위치를 다시 계산한다. 모션 감소 또는 sticky 해제 상태에서는 일반 소개 섹션의 시작점으로 이동한다.
- 앵커 이동 중에도 히어로는 현재 스크롤 진행도에 맞춰 표시한다. 별도의 시간 기반 재생을 시작하거나 사용자의 스크롤 입력을 막지 않는다.
- 현재 읽고 있는 섹션의 메뉴를 강조하고 `aria-current="location"`으로 표시한다. 일반 스크롤마다 방문 기록을 추가하지 않으며, 앵커 탐색의 뒤로·앞으로 이동을 지원한다.
- 키보드로 앵커를 선택하면 도착한 섹션 제목으로 포커스를 전달한다. 모바일은 접이식 GNB를 사용하고 메뉴 선택 시 닫힌 뒤 해당 섹션으로 이동한다.
- GNB의 Let’s talk는 문의 모달을 바로 열지 않고 `#contact`로 이동한다. 그곳의 `문의하기` 버튼이 기존 공통 문의 모달을 연다.

### 첫 장면

- 상단: STUDIO OKK 로고, Studio / Works / Clients / Let’s talk. 메뉴는 단색의 밝은 바탕이나 캡슐 위에 배치한다.
- 중앙 상단: 큰 입체 타이포. 캐릭터가 글자 일부 앞에 겹쳐 깊이를 만들되 주요 단어는 읽혀야 한다.
- 중앙: 정면의 오키키. 데스크톱 기준 높이 약 45~55%를 시작값으로 잡고, 비니와 발이 잘리지 않게 한다.
- 외곽: 흰 구름, 핑크 별 스티커, 노란 메모, 작은 손그림.
- 하단: 짧은 브랜드 문장과 `스크롤해서 스튜디오 만나기 ↓` 안내. 작업으로 바로 이동하는 링크도 제공한다.

### 전환 완료 장면

데스크톱에서는 콘텐츠 폭을 최대 약 1280px로 제한하고 좌우 여백을 확보한다. 왼쪽 45%는 회사 소개, 오른쪽 45%는 캐릭터, 가운데 약 10%는 여백으로 구성한다. 캐릭터는 Y축 회전이 완료된 **후면 모습**으로 오른쪽에 남는다. 정면에서 180도 돌았으므로 완료 시 정면으로 다시 바꾸지 않는다.

소개 카피 초안:

> **즐거운 상상을, 오래 기억될 캐릭터로.**  
> STUDIO OKK는 개성 있는 캐릭터와 유쾌한 시각 언어로 브랜드의 이야기를 그립니다. 작은 아이디어가 사람들의 마음에 남는 특별한 경험이 되도록 함께 만듭니다.

주요 버튼은 `작업 보러 가기` → `#works`, 보조 링크는 `함께 만들기` → `#contact`로 연결한다. 회사 소개는 이미지에 넣지 않고 실제 텍스트로 제공한다. 본문 뒤의 구름과 낙서는 비워 두고, 필요한 경우 불투명한 밝은 패널로 가독성을 확보한다.

## 5. 스크롤 인터랙션 설계

### 기본 동작

히어로와 소개를 하나의 연속 구간으로 구성한다. 화면 안의 무대는 sticky로 유지하고, 실제 스크롤 거리를 0~1의 진행도 `p`로 환산한다. 초기 제안은 데스크톱 전체 구간 240svh, 무대 100svh이며 약 140svh의 스크롤 동안 전환한다. 수치는 화면 높이와 콘텐츠 양에 맞춰 조정한다.

`p = clamp((현재 스크롤 위치 - 구간 시작 위치) / (구간 높이 - 무대 높이), 0, 1)`

회전·위치·배경·텍스트를 모두 같은 진행도에서 계산한다. 아래로 내리면 정방향, 위로 올리면 동일한 경로로 역방향 이동한다. 중간에서 스크롤을 멈추면 그 장면에 머문다. 특정 지점에서 시간 기반 영상을 한 번 재생하는 방식은 사용하지 않는다.

### 장면별 진행표

| 진행도 | 캐릭터 | 배경·입체 타이포 | 회사 소개 |
| --- | --- | --- | --- |
| 0~10% | 중앙, 정면 0도 유지 | 블루 포스터 장면 유지 | 숨김 |
| 10~40% | 오른쪽 이동 시작, 0→75도 회전 | 타이포가 위로 약간 이동하며 흐려짐, 구름이 외곽으로 이동 | 읽을 공간 확보 |
| 40~70% | 오른쪽으로 이동하며 75→150도 회전 | 타이포 사라짐, 왼쪽 배경이 밝아짐 | 약 55%부터 제목·본문이 작은 상승 이동과 함께 나타남 |
| 70~85% | 오른쪽 위치에 정착, 150→180도 회전 | 소개 배경으로 전환 완료 | 제목·본문·버튼 완전히 표시 |
| 85~100% | 오른쪽 후면 유지 | 최종 장면 유지 | 읽고 버튼을 선택할 여유 제공 |

이후 sticky 구간이 끝나면 완성된 소개 장면 전체가 자연스럽게 위로 빠지고 대표 작업이 이어진다. 다시 위로 진입하면 완료 장면부터 역재생한다. 이동 좌표는 화면의 고정 픽셀값 대신 캐릭터 영역과 콘텐츠 영역의 실제 크기로 계산한다.

부드러운 보간을 사용하되 튀어 오르는 탄성이나 과도한 관성은 넣지 않는다. 캐릭터가 소개 영역을 충분히 벗어난 뒤 글을 표시한다. 스크롤 중에는 별도의 클릭 회전·마우스 기울기·자동 호흡이 같은 변환값을 덮어쓰지 않도록 한다.

### 180도 회전 표현

단일 포스터에 CSS `rotateY(180deg)`를 적용하면 이미지가 얇아졌다가 좌우로 뒤집히므로 실제 캐릭터의 측면·후면을 보여줄 수 없다. B안의 목표 표현에는 정면부터 후면까지 연결되는 회전 에셋이 필요하다.

**우선 제안은 투명 배경의 사전 렌더 이미지 시퀀스다.** 기존 PRD의 실시간 3D 모델 제외 범위를 유지하면서 진행도별 각도를 표현할 수 있다. 카메라·조명·크기·중심축을 고정하고 0~180도를 연결한다. 웹에서는 시퀀스가 회전을 표현하고, 별도 컨테이너가 오른쪽 이동과 크기 조정을 담당한다. 시퀀스에 CSS Y축 회전을 중복 적용하지 않는다.

기존 턴어라운드는 외형 검수 자료로 활용한다. 몇 장의 정면·측면·후면 이미지 전환만으로 연속 회전 품질이 확보된 것으로 간주하지 않는다. 회전 에셋 준비 전 레이아웃 검토에는 정지 이미지를 사용하고, 실제 회전은 미완료 상태로 구분한다. 실시간 3D 방식은 모델 확보와 제작 범위 변경이 필요할 때 별도로 검토한다.

## 6. 모바일과 접근성

- 768px 미만은 상하 구성을 기본으로 한다. 전환 완료 시 **위쪽에 왼쪽 정렬 소개, 아래쪽에 오른쪽 정렬 캐릭터**를 둔다. 좌우 2열을 좁은 화면에 축소하지 않는다.
- 첫 장면부터 상단 타이포 영역과 하단 캐릭터 영역을 나눈다. 캐릭터는 하단 중앙에서 하단 오른쪽으로 이동하며 회전한다. 글이 나타나는 상단 영역을 가로지르지 않는다.
- 모바일 타이포는 48~72px에서 폭에 맞춰 조정하고, 캐릭터 폭은 약 160~220px를 시작값으로 삼는다. 좌우 여백 20px, 글과 캐릭터 사이 최소 24px를 확보한다.
- 장식은 1~2개만 남기고, 큰 구름은 가장자리에서 일부만 보이게 한다. 버튼은 최소 44px 높이를 확보하고 줄바꿈 시 세로로 배치한다.
- 모바일 구간은 약 200svh를 시작값으로 검토한다. 짧은 화면·가로 모드·글자 확대에서 소개와 캐릭터가 무대 높이를 초과하면 sticky를 해제하고 일반 문서 흐름으로 배치한다. 내용이 잘리는 고정 높이를 강제하지 않는다.
- 일반 본문 대비 4.5:1 이상, 큰 제목 3:1 이상을 검수 목표로 한다. 텍스트와 버튼 뒤에는 충분히 단순하고 대비가 일정한 바탕을 둔다.
- `prefers-reduced-motion`에서는 회전·이동·패럴랙스와 긴 고정 구간을 생략하고 정적인 히어로 다음에 소개를 보여준다.
- 숨겨진 소개 버튼에 키보드 포커스가 들어가지 않도록 한다. 소개로 직접 이동하거나 키보드로 탐색할 때도 내용을 읽을 수 있도록 스크롤 전환에만 접근을 의존하지 않는다.
- 장식 이미지는 보조기술에서 제외하고, 의미 있는 캐릭터 이미지에는 설명을 제공한다. 회전 프레임마다 설명을 반복하지 않는다.

### 포트폴리오: 캐릭터 자판기

**마음에 드는 캐릭터의 버튼을 누르면, 그 작업의 이야기가 열린다.**

원페이지의 `#works` 섹션을 캐릭터가 진열된 자판기로 표현한다. 코발트블루의 둥근 외장, 밝은 하늘색 진열창, 입체 선반, 도톰한 선택 버튼으로 실제 자판기의 구조를 알아볼 수 있게 만든다. 하늘과 구름 배경 위에 장난감 같은 자판기가 놓인 장면으로 히어로의 분위기를 이어간다. 기존의 공중 부유 배치는 이 구성으로 대체한다.

#### 외형과 진열

- 상단 간판에는 `PICK YOUR CHARACTER`와 작은 STUDIO OKK 로고를 배치한다. 안내 문구는 `버튼을 눌러 작업을 만나보세요`로 제안한다.
- 자판기에 총 6개 항목을 표시하며 데스크톱은 3열 2행으로 배치한다. 한 화면 높이에 맞춰 축소하지 않고 페이지 스크롤로 모두 탐색한다. 각 칸에 프로젝트 대표 캐릭터, 작업명·분야, `A1` 같은 선택 번호, 선택 버튼을 한 묶음으로 배치한다.
- 상품 패키지는 추가 레퍼런스 `자료/ref/B안_자판기.jpg`를 따른다. 6개 상품에 걸이 탭, 파스텔 포인트의 번호 라벨(01~06), 투명한 입체 블리스터 케이스를 적용한다. 캐릭터는 케이스 안에 기울여 배치하고 반사광·테두리 음영·드롭 섀도로 깊이를 준다. 작업명과 상세 선택 버튼은 케이스 아래에 분리해 읽기 쉽게 유지한다.
- 각 칸 바로 아래에 대응하는 물리 버튼 형태의 UI를 둔다. 버튼 문구는 `A1 · 상세 보기`처럼 번호와 기능을 함께 표시하고, 작업명은 항상 보이게 한다.
- 하단 배출구와 작은 스티커는 자판기의 인상을 완성하는 장식으로 사용한다. 구매·결제 절차 없이 선택 한 번으로 작업을 탐색한다.
- 투명 캐릭터 에셋이 없는 프로젝트는 실제 대표 이미지를 패키지나 진열판 형태로 담는다. 작업과 무관한 캐릭터로 대체하지 않는다.

#### 버튼과 상세 화면 동작

1. 대기 상태에서는 모든 작업명과 선택 버튼이 보인다.
2. 호버 또는 키보드 포커스 시 해당 버튼과 진열칸에 조명이 켜져 선택 대상을 명확히 보여준다.
3. 버튼을 누르면 버튼이 살짝 눌리고 해당 진열칸이 짧게 빛난다. 피드백은 약 150~250ms를 제안하며, 긴 배출 연출로 탐색을 기다리게 하지 않는다.
4. 페이지 이동 없이 선택한 프로젝트의 상세 모달을 연다. 작업명·분야·소개·이미지를 보여주고 모바일에서는 전체 화면 형태로 표시한다.
5. 닫기 버튼 또는 Escape로 닫으면 자판기의 스크롤 위치와 선택 버튼의 포커스를 복원한다. 모달을 열 때 방문 기록에 상태를 추가하여 브라우저 뒤로 가기도 모달 닫기로 처리한다. 앞으로 가기로 복원할 때는 해당 작업을 다시 표시한다.

선택 UI는 실제 버튼으로 구현하고 Enter·Space로 열 수 있게 한다. 모달에 제목을 연결하고, 열린 동안 배경 스크롤과 배경 조작을 막으며 키보드 포커스는 모달 내부에 유지한다. 접근 가능한 이름에는 작업명과 ‘상세 보기’를 포함한다. 모션 감소 설정에서는 눌림·조명 전환을 생략하고 바로 상세를 연다. 장식이나 애니메이션이 로드되지 않아도 상세 열기는 작동해야 한다.

#### 모바일 배치

- 모바일에서는 자판기 외장의 두께와 장식을 줄이고 진열칸 6개를 2열 3행으로 배치한다. 좁은 화면이나 글자 확대 상태에서는 1열로 전환한다.
- 각 캐릭터 바로 아래에 작업명과 최소 44px 높이의 선택 버튼을 둔다. 별도의 멀리 떨어진 번호 키패드를 찾을 필요 없이 대응 관계가 보이게 한다.
- 작업 수가 늘어나면 자판기 진열 영역을 세로로 확장하고 일반 페이지 스크롤로 탐색한다. 자판기 내부에 별도의 세로 스크롤을 만들지 않는다.
- 캐릭터·선반·버튼은 겹치지 않게 배치하고 작업명은 줄바꿈을 허용한다. 장식 배출구보다 작업 정보와 버튼의 가독성을 우선한다.

### 클라이언트: 간결한 로고 띠배너

포트폴리오와 문의 사이에 화면 폭을 가로지르는 낮고 긴 띠를 배치한다. 흰색 또는 아주 옅은 하늘색 바탕에 작은 `OUR CLIENTS` 라벨과 로고 행을 두고, 큰 제목이나 개별 카드 장식은 생략한다.

- 기존 15개 로고를 각각 한 번씩 배치한다. 원본 비율과 브랜드 식별성을 유지하고, 시각적 크기를 맞추며 로고 사이 여백을 일정하게 둔다.
- 데스크톱 띠 높이는 약 100~140px를 시작값으로 삼는다. 로고가 모두 들어가지 않으면 로고 영역을 가로 스크롤할 수 있게 하고, 끝까지 탐색할 수 있는 스크롤 표시를 제공한다.
- 모바일에서도 한 줄 띠를 유지하며 손가락으로 가로 탐색한다. 키보드로도 로고 영역을 스크롤할 수 있게 한다.
- 기본안은 자동으로 흐르지 않는 정적인 띠배너다. 캐릭터 자판기 다음에 시각적인 휴식 구간이 되도록 한다.
- 로고 자체에는 링크, 클릭 이벤트, 호버 애니메이션을 넣지 않는다.

구현은 기존 HTML/CSS/JavaScript 구조에서 시작할 수 있다. 진행도 계산과 화면 갱신을 분리하고, 이동·페이드는 transform과 opacity 중심으로 처리한다. 회전 프레임은 필요한 구간을 미리 준비하고 모바일에는 더 작은 해상도를 제공한다. 프레임 수와 파일 용량은 실제 기기에서 회전의 연속성과 메모리 사용량을 함께 확인해 결정한다.

로딩 중에는 크기가 확보된 정지 이미지를 먼저 보여준다. 시퀀스가 실패해도 회사 소개와 작업 탐색은 가능해야 한다. 리사이즈·화면 회전·페이지 재진입 시 진행도를 다시 계산하고, 문의 모달을 닫으면 기존 스크롤 위치와 장면을 복원한다.

## 9. 시안 검수 기준

- GNB의 모든 항목이 같은 페이지의 해당 섹션으로 이동한다. 해시 직접 접속·새로고침·뒤로/앞으로 이동에서도 헤더에 가리지 않고 올바른 섹션을 보여준다.
- Studio 앵커 도착 시 소개가 완전히 보이며, 모바일과 모션 감소 상태에서도 같은 내용을 읽을 수 있다.
- 첫 화면에서 블루 하늘, 폭신한 구름, 입체 타이포, 오키키와 낙서가 하나의 장면으로 읽힌다.
- 아래로 스크롤하면 중앙의 정면 캐릭터가 Y축 기준 정확히 180도 회전하며 오른쪽으로 이동한다.
- 전환 완료 시 데스크톱 왼쪽에 소개, 오른쪽에 후면 캐릭터가 남고, 모바일에서는 상하 영역으로 분리된다.
- 25%·50%·75% 등 중간에서 멈추거나 방향을 바꿔도 장면이 튀거나 처음부터 재생되지 않는다.
- 전환 전후와 중간 구간 모두 본문·버튼이 캐릭터와 장식에 가려지지 않는다.
- 포트폴리오가 캐릭터 자판기로 읽히고, 각 진열칸과 선택 버튼의 대응 관계가 명확하다. 버튼을 누르면 해당 작업 상세 모달이 열리며 닫기·Escape·뒤로 가기 시 탐색 위치와 포커스가 복원된다.
- 자판기는 모바일에서도 작업명과 버튼이 겹치지 않고, 터치·키보드·모션 감소 설정에서 모든 작업을 탐색할 수 있다.
- 클라이언트는 간결한 한 줄 띠배너로 보이고, 모든 로고를 터치와 키보드로 탐색할 수 있다.
- 폭 390px와 1440px를 기본으로, 320px·768px·짧은 가로 화면 및 글자 확대 상태에서도 넘침과 잘림을 확인한다.
- 빠른 스크롤, 터치 스크롤, 키보드 탐색, 모션 감소, 회전 에셋 로딩 실패 상황에서도 소개·작업·문의에 접근할 수 있다.
- 실제 기기에서 회전 프레임 끊김과 스크롤 지연을 확인하고, 작업 상세 모달과 문의 기능이 정상 동작하는지 검수한다.

다음 제작 단계는 데스크톱·모바일의 첫 장면과 전환 완료 장면을 각각 시안으로 구성하고, 회전 에셋을 연결한 스크롤 프로토타입에서 중간 장면을 검토하는 것이다.

## Contact 구현 변경 — 인라인 문의와 차오르는 등장 효과

- Contact에 처음 도달하면 블루 배경이 아래에서 위로 차오르고, 소개와 양식이 함께 상승하며 나타난다. 반복 재생으로 작성 중인 입력을 방해하지 않는다.
- 문의 팝업을 제거하고 회사명·담당자명·연락처·이메일·요청사항과 접수 버튼을 섹션에 직접 노출한다. 앞서 기술한 문의 모달 구성은 이 인라인 구성으로 대체한다. 작업 상세 모달은 유지한다.
- 데스크톱은 좌측 소개·우측 양식의 2열, 모바일은 소개 다음에 전체 양식을 세로로 배치한다. 단계나 접기 없이 모든 항목에 바로 접근한다.
- GNB Let’s talk는 양식이 있는 #contact로 이동한다. 모션 감소 설정과 키보드 입력 시에는 즉시 읽고 조작할 수 있다. 기존 입력 검사·중복 전송 방지·발송 실패 시 입력 보존을 유지한다.
