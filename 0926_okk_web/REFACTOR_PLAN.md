# A 사이트·어드민 구조 최적화 계획

## 범위와 원칙

- A 사이트와 A 전용 Work·Clients 관리자만 변경한다. 분리된 B/B-1은 제외한다.
- 1~3 구현·검증을 마친 다음 4~5를 진행한다.
- 화면, URL, 데이터 형식, 인증·CSRF, 공개 정책, 미리보기 동작을 유지한다.
- 빌드 도구나 프레임워크를 새로 도입하지 않고 브라우저 ES 모듈을 사용한다.
- 주석은 포커스 복원, 비동기 처리 등 코드만으로 드러나지 않는 이유·제약에만 남긴다.
- 기존 로컬 변경과 실제 관리자 데이터를 보존한다. 검증에는 임시 DB를 사용한다.
- 이미지 압축은 이번 범위에서 제외한다. GitHub 푸시·배포는 수행하지 않는다.

## 1단계: 1~3

- [x] 1. CSS를 기반 스타일, 사이트 레이아웃, 히어로, Studio, 문의, 프로젝트 단위로 분리한다. 컴포넌트 안에 반응형 규칙을 모으고 중복 선언을 정리한다.
- [x] 2. 공개 카드·상세와 관리자 미리보기가 프로젝트 CSS와 기반 스타일만 공유하도록 한다. 미리보기에서 사이트 전체 CSS 의존을 제거한다.
- [x] 3. 관리자 공통 API·인증·알림·작업 잠금과 Work·Clients 편집 상태를 분리한다. 메뉴 이동·로그아웃·세션 만료 시 미저장 내용과 포커스 동작을 보존한다.
- [x] 검증: 변경 전후 스타일 비교, 서버 테스트, 관리자 저장·공개·업로드·Clients·미리보기, 모바일 배치와 접근성 검사.

## 2단계: 4~5

- [x] 4. A 진입 코드는 화면 전환만 조정한다. 홈·Studio·Works 렌더링, 히어로 수명주기, 문의 동작, 데이터 로딩을 역할별 모듈로 분리한다.
- [x] 5. 사이트·이미지·공개 API·관리자 API 경로를 공통 경로 모듈로 모은다. `/`와 `/okk/` 진입 및 기존 직접 링크를 유지한다. HTML 초기 리소스 주소는 명시적으로 유지한다.
- [x] 검증: 직접 URL 진입, 내부 이동·뒤로 가기, 지연·실패 응답, 히어로 정리, 문의 검증·오류 시 입력 보존, 공개 화면과 미리보기 일치, 전체 회귀 검사.

## 완료 기준

- 기존 화면의 반응형 배치와 핵심 접근성 동작이 유지된다.
- Work와 Clients가 서로의 편집 변수를 직접 읽거나 변경하지 않는다.
- 미리보기가 히어로·문의·사이트 헤더 CSS를 로드하지 않는다.
- 반복 API·경로 문자열과 전역 스크립트 로드 순서 의존을 줄인다.
- 실행한 검사와 한계를 이 문서에 기록한다.

## 수행 기록

- 계획 작성 완료. 구현 전 화면·스타일 기준 자료를 수집한다.

- 1~3 완료: CSS 6개 영역 분리, 미리보기 전용 CSS 구성, 관리자 API·인증·UI·Work·Clients 모듈 분리.
- 1단계 검증: 서버 테스트 16개, 스타일 50개 상태 비교(차이 0), Work 토글·Clients CRUD·편집 상태 보호 검사 통과. 접근성 11개 상태 위반 0, JS 오류 0.
- 기존 브라우저 검사에서 사라진 재생 버튼 참조와 Work/Clients를 구분하지 않는 선택자를 현재 UI에 맞게 보완했다.

- 4~5 완료: A 진입 파일을 61줄의 화면 조정 코드로 축소하고 화면·히어로·문의·내부 이동·공개 데이터 모듈로 분리했다. 공통 렌더러·이스케이프·경로를 ES 모듈로 공유하며 `window.OKKProject`와 스크립트 로드 순서 의존을 제거했다.
- 히어로를 떠날 때 관찰자·타이머·이벤트를 정리하고, 반복 이동에서도 중복 관찰자가 남지 않음을 검사했다.
- 관리자 미리보기 CSS 원본 파일 크기 합계: 28,980 → 6,478바이트. 네트워크 압축 전 파일 크기이며 실제 로딩 속도 측정값은 아니다.
- 프런트엔드 주석은 입력 검증을 위한 `inert` 임시 해제 이유 한 곳만 유지했다.

## 재검증 방법

```sh
.venv/bin/python checks/serve_review.py
```

별도 터미널에서 서버 검사와 Playwright 검사를 실행한다. 브라우저 검사에는 Playwright·Chrome·로컬 axe-core가 필요하다. Clients 초기 데이터 개수를 검증하므로 전체 검사는 새 임시 서버에서 시작한다.

```sh
.venv/bin/python -m unittest discover -s checks -p 'test_*.py'
AXE_SCRIPT=/tmp/okk-axe.min.js /private/tmp/okk-browser-env/bin/python checks/check_admin_toggle.py
/private/tmp/okk-browser-env/bin/python checks/check_clients.py
/private/tmp/okk-browser-env/bin/python checks/check_editor_state.py
/private/tmp/okk-browser-env/bin/python checks/check_site_modules.py
AXE_SCRIPT=/tmp/okk-axe.min.js /private/tmp/okk-browser-env/bin/python checks/check_review.py
```

스타일 비교 도구는 `checks/check_refactor.py`다. 변경 전에 `record`, 변경 후 동일한 초기 데이터에서 `compare`를 실행한다. 이번 기준 자료는 `/tmp/okk-refactor-styles.json`, 비교 결과는 `/tmp/okk-refactor-style-diff.json`에 있다. 이후 작업의 기준을 만들 때만 다시 기록한다.
