## 1 목적과 제작 범위

스튜디오의 젊고 키치한 분위기와 대표 작업을 전달하는 포트폴리오 사이트를 만든다. 이번 단계의 목표는 시각적 콘셉트, 마스코트 반응, 작업 탐색과 연락하기 흐름을 실제 화면에서 확인하는 것이다.

마스코트는 보유 이미지와 짧은 동작 영상 또는 이미지 시퀀스로 표현한다. 클릭과 스크롤을 재생 트리거로 연결하고, 마우스 움직임은 화면 요소의 가벼운 기울기와 이동으로 반영한다. 실시간 3D 모델 제작은 이번 범위에서 제외한다.

## 4 디자인 방향

깨끗한 공간에 OKK 마스코트와 큼직한 그래픽을 배치한다. 키치한 개성은 캐릭터, 타이포그래피와 작은 스티커 요소로 표현하고, 작업 이미지는 넓고 선명하게 보여준다.

### 시각 원칙

- 확정: 주요 색상은 #004EEA. 히어로는 깨끗한 배경과 대표 마스코트를 중심으로 구성한다.

- 제안: 흰색 또는 아주 밝은 중성색을 바탕으로 사용한다. 

- 제안: 제목에는 개성 있는 굵은 글꼴을 사용하고, 본문과 작업 정보에는 pretndard 글꼴을 적용한다. 최종 서체와 사용 권한은 별도 확인한다.

- 제안: 레트로 창과 픽셀 요소는 Contacts 팝업 등 일부에 적용한다. 

- 제안: 포트폴리오 상세에서는 장식을 줄이고 작업 이미지와 설명의 가독성을 우선한다.

### 대표 캐릭터 설정

- **오키키 (OKK)**: 하늘과 바다의 푸르름, 꿈과 희망을 간직한 푸른 원석에서 태어난 옥돌 소년. 세상에서 가장 독보적인 보석이 되고 싶은 당찬 열망을 품고 있다. 파란 비니는 식지 않는 푸른 꿈의 상징이다. 장난스러운 찡긋한 윙크와 미소, 당차고 쾌활한 매력과 귀여운 뒷모습이 특징이다.
- **오키몽 (OKKIMONG)**: 오키키가 원석일 때부터 곁을 지켜온 신비로운 원숭이 친구. 오키키와 맞춰 쓴 파란 비니, 같은 시그니처 윙크와 하트 같은 뒷모습이 특징이다. 오키키가 외롭거나 좌절할 때 엉뚱함과 장난기로 웃음을 주는 분위기 메이커다.

캐릭터 원본의 외형과 색상을 유지한다. 프로토타입에서는 이미지 전체의 확대·기울기로 반응을 확인하며, 실제 손 흔들기와 표정 변화는 동작 에셋 수령 후 구현한다.

### 모션 방향 제안

마스코트의 동작은 장난스럽고 친근하게, 메뉴와 팝업의 반응은 짧고 명확하게 만든다. 일반 UI 전환은 약 150~250ms를 시작값으로 삼고, 캐릭터 연기는 별도 길이로 제작한다. 애니메이션이 작업 탐색을 기다리게 하지 않도록 한다.

참고 스킬: emil-design-eng는 모션과 UI 반응, design-taste-frontend는 레이아웃과 디자인 일관성 검토에 사용한다. 프로젝트의 확정 요구사항을 우선한다.

## Contacts 팝업과 이메일 접수

확정: 회사명, 담당자명, 연락처, 이메일, 요청사항을 입력하고 접수하기 버튼을 누르면 ouog22@gmail.com으로 메일을 발송한다. 모든 연락하기 진입점은 같은 팝업을 사용한다.

| 순서 | 입력 항목 | 입력 방식 제안 |
| --- | --- | --- |
| 1 | 회사명 | 한 줄 텍스트 입력 |
| 2 | 담당자명 | 한 줄 텍스트 입력 |
| 3 | 연락처 | 전화번호 입력에 적합한 키패드 |
| 4 | 이메일 | 이메일 형식 입력 |
| 5 | 요청사항 | 여러 줄 텍스트 입력 |

입력 항목과 접수 버튼 문구는 확정이다. 필수 여부와 글자 수 제한은 미정이며, 초안에서는 5개 항목을 모두 필수로 제안한다. 각 입력란에는 항상 보이는 라벨과 오류 메시지를 제공한다.

### 접수 처리 제안

- 입력 검사 → 전송 중 → 접수 완료 또는 실패 순서로 표시한다. 전송 중에는 버튼 중복 실행을 막고, 실패하면 입력값을 유지하여 다시 시도할 수 있게 한다.

- 서버에서 입력값을 검사하고 메일 발송 서비스 또는 SMTP로 전송한다. 수신 주소는 서버 설정으로 고정하고 발송 인증 정보는 서버에서 관리한다.

- 메일 제목 제안: [STUDIO OKK 문의] 회사명 / 담당자명. 본문에는 입력한 5개 항목을 포함한다. 발신 주소는 인증된 주소를 사용하고, 답장 주소는 방문자가 입력한 이메일로 설정한다.

- 메일 발송 서비스가 요청을 정상 접수한 경우에만 접수 완료를 표시한다. 서비스 접수와 실제 받은편지함 도착은 구분하여 검수한다. 메일 앱을 여는 방식으로 대체하지 않는다.

구현 전 결정: 발송 서비스, 발신 주소와 인증 설정, 입력 제한, 개인정보 안내 및 동의 방식. 문의 내용의 별도 데이터베이스 저장은 현재 요구사항에 포함되지 않는다. 연속 접수 제한과 기본 스팸 방지는 구현 시 검토한다.

### 팝업 공통 동작

- 공통 동작 제안: 닫기 버튼과 Escape 키 지원, 팝업 내부로 키보드 포커스 이동, 닫으면 실행 버튼으로 포커스 복귀.

- 팝업을 연 동안 배경 스크롤을 잠근다. 작은 화면에서는 내용이 화면을 벗어나지 않도록 내부 스크롤을 허용한다.

- 사용 중인 메뉴 상태와 키보드 포커스를 시각적으로 표시한다. 클릭 가능한 요소는 링크 또는 버튼으로 구현한다.

## 6 마스코트 인터랙션과 구현안

첫 진입 애니메이션과 클릭·스크롤로 손을 흔들거나 웃는 반응은 확정 요구사항이다. 첫 진입 순서는 아래와 같으며, 세부 연출 수치와 이후 동작 배분·재생 규칙은 프로토타입 제작을 위한 제안이다.

### 첫 진입 애니메이션

웹페이지 실행 시 다음 순서로 재생한다.

1. 원이 점점 커지는 인터랙션으로 시작한다.
2. 화면 중앙에서 OKK 캐릭터가 인사하며 확대된다.
3. 확대된 캐릭터 장면이 히어로 영역으로 자연스럽게 이어진다.
4. 히어로로 연결된 뒤 studio okk 타이포가 한 글자씩 순차적으로 떨어져 제자리에 배치된다.

구현 제안: 진입 장면과 히어로 사이에서 캐릭터의 위치와 크기를 연속적으로 전환하여 화면이 끊기거나 갑자기 바뀌지 않게 한다. 타이포 낙하가 끝나면 기본 히어로 상태로 전환한다. 원의 색상과 확대 범위, 단계별 재생 시간, 글자별 시차와 낙하 곡선은 프로토타입에서 조정한다.

재생 규칙 제안: 최초 페이지 로드에 1회 재생하고 내부 페이지 이동 시 반복하지 않는다. 진입 연출 중 클릭·스크롤 반응은 중복 재생하지 않으며, 방문자가 스크롤로 탐색을 시작하면 연출을 마무리하고 기본 히어로 상태로 전환한다. 모션 감소 설정 또는 에셋 로딩·재생 실패 시에는 원 확대와 캐릭터 확대, 타이포 낙하를 생략하고 캐릭터 정지 이미지와 완성된 타이포를 표시한다.

### 구현 순서 제안

1. 단독 마스코트 기준 이미지를 준비한다. 카메라, 배경, 크기와 조명을 고정하고 진입 인사·대기·클릭 반응·스크롤 반응 에셋을 제작한다. 진입 인사에는 클릭 반응 에셋의 재사용 가능 여부를 검토한다. 영상 생성 결과에서 얼굴, 손가락, 모자와 로고가 유지되는지 검토한다.

2. HTML video와 정지 이미지로 먼저 구성한다. 음소거와 인라인 재생을 적용하고 재생 실패를 처리한다. 같은 색의 배경을 사용해 영상의 사각 경계가 보이지 않도록 맞춘다.

3. 첫 진입·대기·클릭 반응·스크롤 반응을 상태로 관리한다. 첫 진입에서는 원 확대, 캐릭터 인사와 확대, 히어로 연결, 글자별 낙하를 순서대로 제어한다. 진입 완료 후에는 클릭 반응을 우선하고, 그동안 발생한 스크롤 반응은 중복 재생하지 않는다. 화면 밖에서는 영상 재생을 일시 정지한다.

4. 프레임 단위 제어가 꼭 필요할 때만 이미지 시퀀스를 검토한다. 이번 기본안은 스크롤 지점에서 영상을 재생하는 방식이며, 스크롤 위치마다 영상 프레임을 맞추는 방식은 필수가 아니다.

### 기술 구성과 품질 원칙 제안

페이지와 공통 팝업을 분리하고 작업 데이터를 한 곳에서 관리한다. CSS transform·opacity로 이동과 전환을 표현하고, 화면 진입 감지로 재생을 제어한다. 프레임워크와 라이브러리 버전은 개발 착수 시 결정한다.

첫 화면의 크기를 미리 확보해 로딩 시 레이아웃이 흔들리지 않도록 한다. 정지 이미지를 우선 노출하고 영상과 하단 작업 이미지는 필요한 시점에 불러온다. 모바일에서는 포인터 추적을 끄고 주요 터치 영역을 충분히 확보한다.

### 프로토타입 완료 기준

- 메인의 히어로, 대표 작업, 클라이언트, 연락하기가 지정한 순서로 표시된다.

- 깨끗한 배경, #004EEA, OKK 마스코트와 젊고 키치한 분위기를 화면에서 검토할 수 있다.

- 웹페이지 실행 시 원 확대 → 중앙에서 인사하는 캐릭터 확대 → 히어로로 자연스럽게 연결 → studio okk 타이포의 글자별 낙하 순서가 확인된다. 완료 후 기본 히어로 인터랙션으로 이어진다.

- 첫 진입 연출 중에도 스크롤 탐색이 가능하고 반응이 중복 재생되지 않는다. 모션 감소 설정 또는 에셋 실패 시 캐릭터 정지 이미지와 완성된 타이포가 표시된다.

- 클릭 또는 터치 시 캐릭터 반응이 1회 재생되고 대기로 복귀한다. 연타해도 화면이 멈추거나 재생이 누적되지 않는다.

- 스크롤 반응이 지정 지점에서 발생하며 일반 페이지 스크롤과 작업 탐색을 방해하지 않는다.

- 대표 작업을 선택하면 해당 상세 내용을 볼 수 있고 목록으로 돌아갈 수 있다. 클라이언트 로고에는 동작이 없다.

- 연락하기로 팝업을 열고 닫을 수 있다. 키보드 조작, 모바일 터치, 모션 감소 및 영상 실패 상황을 확인한다.

- 문의 5개 항목과 접수하기 버튼이 표시된다. 입력 오류·중복 클릭·발송 실패를 처리하고, 전송 결과에 맞게 상태를 표시한다. 발송 기능 검수에서는 지정 주소 수신과 5개 항목의 본문 포함 여부를 확인한다.

- 폭 390px와 1440px를 기본 검토 크기로 삼고, 중간 크기에서도 가로 넘침과 글자·버튼 겹침이 없는지 확인한다.
