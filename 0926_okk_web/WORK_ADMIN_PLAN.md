# Work 프로젝트 관리 어드민 구현 계획

작성일: 2026-09-28

상태: A안 대상 1차 구현 완료. Python + SQLite와 서버 영구 디스크를 사용하는 운영 구성을 준비했다. 실제 호스팅·도메인 연결은 배포 시 진행한다. 실행·운영 안내는 `ADMIN_GUIDE.md`를 참고한다.

## 목표

프로젝트 데이터를 한곳으로 통합하고, 어드민에서 프로젝트를 등록·수정·공개하면 Work 화면에 반영되도록 한다.

## 현재 구현 상태

- **A안**: `public/app.js`에 임시 프로젝트 6개가 있으며, 목록과 개별 상세 페이지를 제공한다.
- **B/B-1안**: 각 `app.js`에 캐릭터 쇼케이스 6개가 있으며, 상세 모달로 연결된다.
- **서버**: `server.py`는 Python 기반 로컬 검토용 서버로, 문의 발송을 처리한다. 프로젝트 저장소, 관리자 로그인, 이미지 업로드는 아직 없다.
- **카드 표현**: B/B-1의 카드 이미지와 색상이 배열 순서에 연결되어 있다. 관리자가 순서를 바꿔도 프로젝트의 표현이 유지되도록 데이터 기준으로 변경해야 한다.

## 1. 어드민 화면 구성

접속 경로는 `/admin/`으로 두고, 로그인 후 프로젝트 목록을 바로 보여준다.

| 화면 | 주요 기능 |
|---|---|
| 로그인 | 관리자 로그인, 로그아웃, 세션 만료 처리 |
| 프로젝트 목록 | 썸네일·제목·클라이언트·공개 상태·수정일, 검색 및 상태 필터 |
| 프로젝트 등록·수정 | 기본 정보 입력, 이미지 업로드, 상세 내용 편집 |
| 노출 순서 관리 | 드래그 또는 위아래 버튼으로 순서 변경 |
| 미리보기 | 저장된 초안을 실제 Work 카드·상세 형태로 확인 |

### 디자인 방향

- 기존 OKK의 파란색과 둥근 요소를 이어간다.
- 밝은 배경과 명확한 입력 영역으로 관리 작업에 집중할 수 있게 구성한다.
- 데스크톱: 왼쪽 편집 폼 + 오른쪽 미리보기.
- 모바일: 편집 폼과 미리보기를 세로로 배치한다.

## 2. 프로젝트 관리 항목

| 구분 | 항목 |
|---|---|
| 기본 정보 | 프로젝트명, 영문명 또는 부제, URL 식별자, 한 줄 소개 |
| 작업 정보 | 클라이언트, 제작 연도, 작업 범위·카테고리 |
| 이미지 | 목록용 썸네일, 상세 대표 이미지, 상세 이미지 여러 장 |
| 상세 내용 | 프로젝트 설명, 이미지별 설명·대체 텍스트, 이미지 순서 |
| 노출 설정 | 초안·공개·비공개 상태, 목록 순서, 메인 노출 여부 |
| 카드 표현 | 배경색, B/B-1용 이미지 또는 기존 캐릭터 표현 선택 |

상세 편집은 우선 설명과 이미지 갤러리로 구성한다. 현재 상세 화면을 수용하면서 프로젝트를 쉽게 추가할 수 있도록 한다.

## 3. 저장과 공개 흐름

새 프로젝트 → 초안 저장 → 미리보기 → 공개 → Work에 반영

- 초안은 관리자에게만 보인다.
- 공개 중인 프로젝트를 수정할 때는 수정 초안을 별도로 저장한다. 방문자에게는 기존 공개본을 보여주고, ‘변경사항 공개’ 시 수정 내용을 반영한다.
- 삭제는 휴지통 이동으로 처리해 복구할 수 있게 한다.
- 이미지 업로드 실패나 저장 실패 시 입력 내용을 유지한다.
- 저장하지 않고 페이지를 나가면 안내한다.

## 4. 구현 구조

기존 HTML/CSS/JavaScript 화면에 Python 프로젝트 API와 SQLite 저장소를 추가하는 구성을 제안한다.

- 프로젝트 조회·등록·수정·공개·정렬 API를 구현한다.
- 관리자 인증은 서버에서 검사하고, 비밀번호는 해시로 저장한다.
- 공개 API는 공개된 데이터만 반환한다.
- 이미지 업로드는 파일 형식·용량을 검증하고, 비공개 자료 접근도 제어한다.
- DB와 업로드 파일은 함께 백업할 수 있게 구성한다.
- 기존 `server.py`는 로컬 검토용이므로, 실제 운영 단계에는 운영용 서버 실행 구성과 HTTPS를 준비한다.

### 기존 사이트 연결

- 사용자 확정에 따라 A안만 공통 프로젝트 데이터를 읽도록 연결한다. B/B-1은 기존 데이터를 유지한다.
- 기존 상세 페이지와 상세 모달 표현은 각각 유지한다.
- A안의 홈·Work 목록·상세 페이지에 공개본을 연결한다.
- 기존 콘텐츠와 연결 주소를 보존하도록 데이터 이전과 라우팅을 설계한다.

## 5. 구현 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 데이터 구조 정리·기존 데이터 이전 | 기존 콘텐츠와 연결 주소를 보존하고 순서를 바꿔도 카드 표현이 유지됨 |
| 2 | 저장소·인증·프로젝트 API | 재시작 후에도 데이터가 유지되고 비로그인 수정이 차단됨 |
| 3 | 어드민 목록·편집·업로드 | 프로젝트 생성부터 이미지 정렬·수정·복구까지 가능 |
| 4 | 미리보기·공개·사이트 연결 | 초안은 숨겨지고 공개한 내용과 순서가 Work에 반영됨 |
| 5 | 사용 흐름 검증 | 모바일 편집, 업로드 실패, 세션 만료, 기존 상세 이동을 확인 |

## 6. 첫 구현 범위와 추후 확장

첫 구현은 관리자 1명 기준의 프로젝트 관리로 진행한다.

추후 확장 항목:

- 다중 관리자와 권한 관리
- 예약 공개
- 방문 통계

## 7. 구현 시 확정할 사항

- 확정된 연결 대상: A안만 연결
- 실제 운영 배포 환경과 데이터·업로드 파일의 영속 저장 위치
- 관리자 계정은 `manage.py admin` 명령으로 설정
- 실제 프로젝트 자료와 필수 입력 항목

## 8. 구현 결과와 범위 조정

- Flask API, SQLite 저장소, 서버 세션, 이미지 검증·WebP 변환을 구현했다.
- 공개본과 수정 초안을 분리하고, 비공개 이미지의 직접 접근을 제한했다.
- 목록 순서와 상세 이미지 순서는 위·아래 버튼으로 변경한다.
- A안 렌더러를 공유하는 카드·상세 미리보기를 제공한다.
- B/B-1용 카드 표현 설정은 A안만 연결한다는 확정에 따라 제외했다.
- 초기 계정 설정, 백업 명령, Gunicorn·HTTPS 프록시 설정 예시를 추가했다.
- 실제 인터넷 배포, SMTP 발송 검증, 외부 백업 예약은 운영 환경 설정 후 진행한다.

## 9. 어드민 입력·공개 방식 변경

- 영문명·부제 입력을 제외하고 상세 상단은 `STUDIO OKK / WORK`로 고정한다.
- 카드 배경색 선택을 어드민에서 제외한다.
- 이미지 업로드 영역에 용도별 비율·권장 해상도·표시 방식을 안내한다.
- 저장 버튼의 문구를 ‘저장’으로 변경한다.
- 공개는 기본 OFF인 토글로 조작한다. ON 전환 시 저장과 공개를 함께 처리하고, 공개 중 저장은 사이트에 바로 반영한다. OFF 전환은 입력 중인 내용을 보존하면서 즉시 비공개 처리한다.
- 서버 회귀 테스트 11개와 토글·저장·실패 복구·접근성·모바일 브라우저 검증을 통과했다.
