# Work 어드민 실행·운영 안내

A 화면(`/okk/`, `/okk/works`, `/okk/works/:slug`)에 연결된 관리자 페이지입니다. B/B-1의 프로젝트 데이터와 화면은 기존 파일을 그대로 사용합니다.

## 로컬 실행

프로젝트 폴더에서 실행합니다. Python 3.11 이상을 사용합니다.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py admin
.venv/bin/python server.py
```

`manage.py admin`은 아이디와 비밀번호를 터미널에서 입력받습니다. 비밀번호는 12자 이상이며 화면에 표시되지 않습니다. 동일 명령으로 관리자 계정을 재설정할 수 있고, 재설정하면 기존 로그인 세션이 모두 만료됩니다. 기본 계정·기본 비밀번호는 없습니다.

- 사이트: http://localhost:3000/okk/
- 프로젝트 목록: http://localhost:3000/okk/works
- 관리자: http://localhost:3000/admin/

기본 데이터는 `data/okk.sqlite3`, 업로드는 `data/uploads/`에 저장됩니다. 서버를 재시작해도 유지됩니다. 최초 실행 시 A안의 기존 임시 프로젝트 6개를 이전합니다. 실제 프로젝트 실적으로 보완하거나 비공개·휴지통 처리할 수 있습니다.

`.env.example`은 설정 예시이며 `.env` 파일을 자동으로 읽지 않습니다. 로컬에서는 셸 환경변수, 운영에서는 아래의 서비스 환경 파일을 사용합니다.

## 프로젝트 관리

1. 로그인 후 ‘프로젝트 등록’을 누릅니다.
2. 제목과 URL 식별자를 입력합니다. 식별자는 영문 소문자·숫자·하이픈을 사용하며 생성 후 고정됩니다.
3. 클라이언트·연도·작업 범위·소개·설명을 입력하고 이미지를 업로드합니다.
4. ‘저장’으로 보관합니다. 오른쪽에서 실제 A 화면 형식의 카드·상세 미리보기를 확인합니다.
5. 새 프로젝트의 공개 토글은 OFF입니다. ON으로 전환하면 현재 내용을 저장하고 공개합니다. 공개 중에는 ‘저장’으로 수정 내용도 사이트에 반영됩니다. OFF로 전환하면 즉시 비공개가 됩니다.

공개 OFF 상태에서 저장하면 방문자에게 노출되지 않습니다. OFF 전환 시 아직 저장하지 않은 입력은 화면에 유지되며 별도로 저장할 수 있습니다. 목록에서 비공개 전환·휴지통 이동·복구가 가능합니다. 휴지통에서 복구하면 비공개 상태이며 다시 ON으로 전환해야 합니다.

영문명·부제와 카드 배경색은 어드민 입력 항목에서 제외했습니다. 상세 상단 문구는 `STUDIO OKK / WORK`로 고정됩니다.

목록의 위·아래 버튼은 전체 프로젝트 순서를 기준으로 인접 프로젝트와 순서를 바꾸고 즉시 반영합니다. 검색·필터를 해제하면 전체 순서를 확인하기 쉽습니다. 메인 노출을 체크한 공개 프로젝트만 홈의 Selected Works에 표시됩니다.

### 이미지와 저장

| 용도 | 비율 | 권장 업로드 해상도 | 표시 방식 |
|---|---|---|---|
| 목록 썸네일 | 4:3 | 1,600 × 1,200px | 다른 비율은 중앙 기준 자르기 |
| 상세 대표 이미지 | 권장 16:9 | 1,920 × 1,080px | 다른 비율도 원본 비율 유지 |
| 상세 이미지 | 자유 | 가로 1,920px, 세로 3,200px 이내 | 긴 이미지는 나누어 업로드 권장 |


- JPG·PNG·WebP, 파일당 최대 12MB, 최대 2,400만 화소를 받습니다. 요청 전체 크기 제한 때문에 정확히 12MB인 파일은 폼 데이터 크기를 포함하면 거부될 수 있습니다.
- 서버에서 실제 이미지를 디코딩하고 최대 3200px WebP로 다시 저장합니다. 메타데이터를 넘기지 않으며 애니메이션은 첫 프레임으로 저장합니다.
- 상세 이미지는 최대 40장이고, 순서·대체 텍스트·설명을 편집할 수 있습니다.
- 이미지 URL은 공개본에서 사용 중일 때만 비로그인 방문자가 조회할 수 있습니다. 관리자는 초안 이미지도 조회할 수 있습니다.
- 공개 해제 후에는 해당 이미지를 공개본에서 사용하는 다른 프로젝트가 없으면 비로그인 접근이 차단됩니다. 이미 다운로드한 자료를 회수하는 기능은 아닙니다.
- 이미지 파일은 교체·휴지통 이동 후에도 남습니다. 초기 버전에는 영구 삭제와 미사용 이미지 정리 기능이 없습니다.
- 8시간 후 세션이 만료되면 재로그인 창이 열리고 현재 편집 내용은 유지됩니다. 페이지 새로고침 전에는 저장해야 합니다.
- 같은 프로젝트를 여러 창에서 수정하면 버전 충돌을 안내합니다. 저장 실패 시 입력 내용을 복사한 뒤 목록을 새로고침합니다.

## 운영 배포

구성: **Linux 서버 한 대 + Gunicorn + SQLite + 영구 디스크 + HTTPS 프록시**.

프로젝트에 `deploy/okk.service`와 `deploy/Caddyfile` 예시를 포함했습니다. 호스팅 계정·서버·실제 도메인은 아직 연결하지 않았습니다. 아래 경로와 계정은 예시이므로 실제 서버 구성에 맞게 적용합니다.

1. 서버에 Python과 Caddy를 설치하고, 전용 `okk` 사용자를 만듭니다.
2. 소스 코드를 `/opt/okk`에 두고 가상환경과 의존성을 설치합니다.
3. `/var/lib/okk`를 만들고 `okk` 사용자가 읽고 쓸 수 있게 설정합니다. 이 폴더는 재배포 시 교체하지 않습니다.
4. `/etc/okk.env`에 아래 환경변수를 설정합니다. 파일 접근 권한은 서버 관리자에게만 허용합니다.
5. 동일한 `OKK_DATA_DIR` 환경에서 `manage.py admin`을 `okk` 사용자로 실행해 관리자 계정을 생성합니다.
6. 서비스 예시를 systemd에 등록하고 실행합니다. Gunicorn은 `127.0.0.1:3000`에서만 수신합니다.
7. 실제 도메인의 DNS를 서버로 연결하고 Caddyfile의 도메인을 변경합니다. 외부에는 HTTPS 프록시만 노출합니다.
8. 로그인·프로젝트 공개·이미지 접근·문의 메일을 실제 도메인에서 확인합니다.

환경 파일 예시:

```ini
OKK_ENV=production
OKK_ORIGIN=https://studio.example.com
OKK_DATA_DIR=/var/lib/okk
```

`OKK_ORIGIN`은 관리자와 사이트가 사용하는 정확한 출처(프로토콜 + 도메인, 경로 없음)여야 합니다. 운영 모드에서는 HTTPS 출처 설정 없이는 서버가 시작하지 않습니다. 쿠키는 Secure·HttpOnly·SameSite=Strict로 설정되고, 수정 요청은 출처와 CSRF 토큰을 검증합니다. 관리자 비밀번호는 해시로 저장하며 로그인 시도는 서버 전체 기준 5분당 30회로 제한합니다.

수동 운영 실행 예시:

```sh
.venv/bin/gunicorn --workers 2 --bind 127.0.0.1:3000 --timeout 60 'cms:create_app()'
```

SQLite 파일은 같은 서버의 영구 로컬 디스크에 둡니다. 여러 서버 복제본이나 공유 네트워크 디스크를 사용하는 구성은 이 배포 범위에 포함하지 않습니다. 정적 호스팅만으로는 관리자 API를 실행할 수 없습니다.

문의 발송은 기존 `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `SMTP_USER`, `SMTP_PASSWORD` 설정을 사용합니다. 미설정 시 실패 안내와 입력 보존을 유지합니다.

## 백업·복구

서비스와 동일한 `OKK_DATA_DIR` 설정으로 실행합니다.

```sh
.venv/bin/python manage.py backup --destination /path/to/backups
```

시간별 폴더 안에 SQLite 일관된 스냅샷과 전체 업로드 폴더를 저장합니다. 이미지 파일은 불변이고 자동 삭제하지 않으므로 DB 스냅샷 이후 파일 복사를 해도 그 스냅샷의 참조가 유지됩니다. 백업에는 비밀번호 해시가 포함되므로 접근을 제한합니다. 로그인 세션은 백업에서 제거됩니다.

운영 서버에서 이 명령을 매일 실행하도록 예약하고, 백업을 별도 저장소로 복사하며 보관 기간을 정합니다. 예약과 외부 저장소 연결은 실제 배포 환경에서 설정해야 합니다.

복구 시 서비스를 중지하고, 현재 데이터 폴더를 별도 보관한 뒤 백업 폴더의 `okk.sqlite3`와 `uploads/`를 새 데이터 폴더에 함께 복원합니다. 기존 DB의 `-wal`·`-shm` 파일을 섞지 않습니다. 소유권을 `okk`로 맞추고 서비스를 시작한 뒤 다시 로그인해 확인합니다.

## Clients 관리

관리 메뉴에서 **Clients 관리**를 선택합니다. 기존 메인 화면의 로고 15개는 최초 실행 시 한 번만 등록되며 순서와 노출 상태가 유지됩니다.

- **클라이언트 등록 / 편집**: 클라이언트명과 로고를 입력하고 저장합니다. 이름은 이미지 대체 텍스트로 사용됩니다.
- **메인 화면에 노출**: 새 항목은 기본 OFF입니다. ON으로 저장하면 A 메인 화면에 표시됩니다. OFF로 저장하면 숨겨집니다.
- **로고**: 권장 800 × 360px(20:9), 투명 PNG·WebP. JPG도 지원하며 최대 12MB·2,400만 화소입니다. 로고는 비율을 유지해 잘리지 않고 표시됩니다.
- **순서**: 목록의 위로·아래로 이동 버튼으로 전체 목록의 순서를 변경합니다. 검색·필터 중에도 전체 순서를 기준으로 이동합니다.
- **휴지통 / 복구**: 휴지통으로 이동하면 즉시 숨겨집니다. 복구하면 비노출 상태이므로 편집에서 ON으로 저장해주세요.

이 변경은 A 메인 화면의 CLIENTS에만 적용됩니다. 저장 데이터와 업로드 파일은 기존 백업에 포함됩니다. 비노출 클라이언트의 업로드 로고는 로그인 없이 접근할 수 없습니다. 같은 이미지를 다른 공개 프로젝트나 노출 클라이언트에서 사용하는 경우에는 공개 접근이 유지됩니다. 기존 정적 로고 파일은 공개 에셋으로 유지됩니다.

## Render Free 테스트용 관리자 계정

Shell 없이 최초 계정을 생성하려면 Render 서비스의 Environment에 아래 값을 설정하고 재배포합니다.

- `OKK_ADMIN_USERNAME`: 원하는 관리자 아이디
- `OKK_ADMIN_PASSWORD`: 12~1024자 비밀번호 (Git에 저장하지 않습니다)

관리자가 없는 DB에서만 계정을 생성하며 비밀번호는 해시로 저장합니다. 두 값 중 하나만 설정하거나 길이 제한에 맞지 않으면 시작 시 오류가 발생합니다. 기존 계정은 재시작이나 환경변수 변경으로 덮어쓰지 않습니다. 기존 계정 재설정은 `python manage.py admin`을 사용합니다.

배포 후 `/admin/`에서 로그인합니다. Free 테스트에서는 DB 초기화 후 계정이 다시 생성되도록 환경변수를 유지합니다. Render Free의 로컬 SQLite와 업로드 파일은 재배포·재시작·절전 시 사라집니다. 계정 자동 생성은 게시물이나 이미지를 복원하지 않습니다. 실제 운영에는 영구 저장소가 필요합니다.
