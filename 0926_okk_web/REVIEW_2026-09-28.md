# 구현 검토 및 개선 결과

검토일: 2026-09-28

검토 범위: A 화면의 홈·Studio·Work 목록·상세·문의, Work 어드민과 미리보기, B/B-1의 공통 접근성 항목. 어드민 데이터 연결 대상은 A안이다.

## 1. 주석과 코드 정리

- CSS의 과거 디자인 변경 설명과 코드만으로 알 수 있는 주석을 제거했다.
- 해시 스크롤 보정, 고정 화면 위치 계산, 불변 이미지 백업 순서, 식별자 고정처럼 이유가 필요한 주석만 짧게 남겼다.
- 어드민 JavaScript를 입력·저장·목록·이미지·인증 흐름별로 읽기 쉽게 정리했다.
- 어드민 CSS의 한 줄 압축 형식을 풀었다.
- 사용하지 않는 A안의 `placeholder()` 함수를 제거하고 README 설명을 수정했다.
- 프로젝트 카드와 상세는 기존 공통 렌더러를 계속 사용한다.

### 검사 결과

- axe-core 4.10.3의 WCAG 2.0/2.1/2.2 A·AA 관련 태그와 best-practice 검사 사용.
- 13개 화면 상태에서 자동 검사 위반 0건.
- 검사 상태: A 홈·Studio·Work 목록·상세, B, B-1, 관리자 로그인·목록·편집·재로그인, 문의 대화상자, 상세·카드 미리보기.
- 키보드 본문 바로가기, 섹션 이동, 문의 대화상자 포커스·Escape 복원, 로그인 후 포커스, 필수 입력 오류 포커스, 프로젝트·이미지 순서 변경 후 포커스를 확인했다.
- 320px·390px·768px에서 검사 대상 화면의 가로 넘침을 확인했다.
- 자동 재생 정지, 화면 밖 캐릭터 정지, 로고 정지 상태 유지, 등록·업로드·공개·휴지통·복구 흐름을 브라우저로 확인했다.
- 브라우저 검사 중 JavaScript 오류 0건.

자동 검사 통과를 전체 접근성 준수 인증으로 해석하지 않는다. 다음 항목은 실제 콘텐츠와 보조기기 환경에서 추가 확인이 필요하다.

- VoiceOver·NVDA로 읽기 순서, 상태 안내, 캐릭터 놀이터 사용성 확인.
- 사진·그라데이션·반투명 배경 위 문구의 모든 화면 상태 대비. axe가 계산하지 못한 항목은 미확인 목록으로 남긴다.
- 실제 프로젝트 이미지의 대체 텍스트 품질. 현재는 입력이 없으면 프로젝트 제목을 사용한다.
- 실제 모바일 기기에서 확대·터치·가상 키보드 사용성 확인.

기준 참고: [WCAG 2.2](https://www.w3.org/TR/wcag/), [자동 움직임의 일시 정지·정지·숨기기](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide), [axe-core 검사 범위](https://www.deque.com/axe/axe-core/).

## 3. 적용한 최적화와 오류 수정

| 항목 | 개선 내용 |
|---|---|
| 첫 화면 표시 | 프로젝트 API 응답을 기다리지 않고 사이트 기본 화면을 먼저 렌더링하고, 도착한 작업 목록만 갱신 |
| 미리보기 갱신 | 연속 입력을 160ms 단위로 모아 iframe 전체 재렌더링 빈도 감소 |
| 여러 이미지 업로드 | 각 파일마다 이미지 편집 목록을 재생성하지 않고 작업 종료 시 한 번 갱신. 중간 실패 시 성공한 업로드는 유지 |
| 이미지 디코딩 | 목록·미리보기 등에 비동기 디코딩과 지연 로딩 적용 |
| 캐릭터 재생 | 화면 밖이나 비활성 탭에서는 정지 이미지로 전환 |
| 이미지 권한 검사 | 요청마다 공개 프로젝트 전체 JSON을 읽는 방식에서 `published_media` 인덱스 조회로 변경 |
| 기존 DB 호환 | 기존 공개본의 이미지 참조를 최초 시작 시 자동 이전하고, 공개·비공개 변경과 같은 트랜잭션으로 관리 |
| 이미지 투명도 | 팔레트 PNG의 투명도를 WebP 변환 시 유지하도록 수정 |
| 잘못된 프로젝트 경로 | 존재하지 않는 작업 화면의 홈 링크에 `${BASE}` 문자열이 그대로 남던 문제 수정 |

추가한 서버 회귀 테스트를 포함해 총 9개 테스트가 통과했다. 기존 인증·공개본 분리·백업 검증에 더해 공유 이미지의 공개 권한, 기존 데이터 인덱스 이전, PNG 투명도 보존을 검사한다.

## 4. 후속 최적화 우선순위

| 우선순위 | 항목 | 근거·진행 방향 |
|---|---|---|
| 높음 | 히어로 애니메이션 용량 축소 | 두 파일이 각각 17,270,328바이트와 12,903,412바이트, 합계 약 30.2MB다. 1080×1350 원본 무손실 애니메이션을 사용한다. 웹 표시 크기에 맞춘 해상도·압축 변형을 제작하고 투명도·화질·동작을 비교하는 것이 다음 성능 개선의 우선 과제다. |
| 중간 | 목록용 이미지 변형 | 현재 목록에서도 업로드 이미지 원본 WebP를 사용한다. 프로젝트가 늘면 작은 썸네일과 srcset을 제공해 전송량을 줄인다. |
| 중간 | 프로젝트 API 분리·페이지 구분 | 현재 프로젝트 전체 내용과 이미지 목록을 한 번에 가져온다. 데이터 증가 시 목록용 요약 응답과 상세 조회를 분리하고 어드민 목록을 페이지로 나눈다. |
| 중간 | 사용하지 않는 업로드 관리 | 이미지 파일은 불변으로 보관되고 자동 삭제하지 않는다. 사용량 표시와 참조 확인 후 정리 기능을 추가하면 저장 비용을 줄일 수 있다. |
| 배포 시 | 압축·성능 측정 | 실제 HTTPS 환경에서 텍스트 응답 압축과 모바일 네트워크 기준 LCP·CLS·INP를 측정한다. 로컬 기능 테스트 결과를 운영 성능 수치로 대체하지 않는다. |

비공개 전환 즉시 이미지 접근을 차단하는 현재 동작을 유지하기 위해 업로드 이미지 응답의 `no-store`는 유지했다.

## 5. 재검증 방법

서버 테스트:

```sh
.venv/bin/python -m unittest discover -s checks -p 'test_*.py'
```

브라우저 검토는 실제 관리자 데이터와 분리된 임시 서버를 사용한다.

```sh
.venv/bin/python checks/serve_review.py
```

별도 터미널에서 Playwright가 설치된 Python과 Chrome, 로컬 axe-core 파일을 사용한다.

```sh
AXE_SCRIPT=/path/to/axe.min.js python checks/check_review.py
```

기본 검증 URL은 `http://127.0.0.1:3098`이며, 해당 임시 서버에서만 사용하는 테스트 계정으로 로그인한다. `OKK_REVIEW_URL`, `OKK_TEST_USERNAME`, `OKK_TEST_PASSWORD`로 검증 환경을 지정할 수 있다. 실제 운영 URL에 실행하면 테스트 프로젝트가 생성되므로 임시 서버를 사용한다.

브라우저 검증 결과는 기본 `/tmp/okk-review-result.json`에 저장된다. 이 검토 시점의 결과 사본은 `checks/accessibility-review.json`에 보관한다.
